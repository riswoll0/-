# Телеграм-бот «Личный кабинет» на Netlify

Бот работает через **webhook** (Telegram сам стучится к вашей функции на Netlify),
а не через постоянный опрос (polling) — это единственный вариант, подходящий
для serverless-хостинга вроде Netlify, где код не работает 24/7, а запускается
только по запросу.

Все данные (список персонала, менеджмент, баксы, промежуточные состояния диалогов)
хранятся в **Netlify Blobs** — встроенном key-value хранилище Netlify. Отдельную
базу данных поднимать не нужно.

## Структура проекта

```
tg-netlify-bot/
├── netlify.toml                 — конфиг Netlify
├── package.json
├── set-webhook.js                — скрипт для настройки вебхука
└── netlify/
    └── functions/
        ├── bot.js                — точка входа (обрабатывает апдейты от Telegram)
        └── lib/
            ├── telegram.js       — обёртка над Telegram Bot API
            ├── storage.js        — работа с Netlify Blobs (персонал, менеджмент, диалоги)
            └── handlers.js       — вся бизнес-логика бота
```

## Шаг 1. Создайте бота и получите токен

1. Напишите **@BotFather** в Telegram → `/newbot` → следуйте инструкциям.
2. Получите токен вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`.

## Шаг 2. Выложите код на Netlify

Вариант А — через Git (рекомендуется):
1. Создайте репозиторий на GitHub и залейте туда содержимое папки `tg-netlify-bot`.
2. На [app.netlify.com](https://app.netlify.com) → **Add new site → Import an existing project** → выберите репозиторий.
3. Netlify сам подхватит `netlify.toml` и папку `netlify/functions`.

Вариант Б — Netlify CLI (без Git):
```bash
npm install -g netlify-cli
cd tg-netlify-bot
npm install
netlify deploy --prod
```

## Шаг 3. Настройте переменные окружения

В настройках сайта: **Site configuration → Environment variables** добавьте:

| Переменная            | Назначение                                                                 |
|-----------------------|-----------------------------------------------------------------------------|
| `BOT_TOKEN`           | токен бота от BotFather                                                    |
| `INITIAL_MANAGEMENT`  | ники ТГ (без @) первых менеджеров через запятую, напр. `ivanov,petrov`     |
| `WEBHOOK_SECRET`      | (необязательно) любая случайная строка для защиты вебхука                 |

После добавления переменных сделайте **повторный деплой** (Deploys → Trigger deploy),
чтобы функция подхватила новые переменные.

Также включите **Netlify Blobs**: они работают «из коробки» для сайтов, задеплоенных
через Netlify (ничего дополнительно настраивать не нужно, пакет `@netlify/blobs`
сам подключается к хранилищу текущего сайта).

## Шаг 4. Привяжите вебхук к вашему сайту

Локально (у себя на компьютере, где установлен Node.js):
```bash
BOT_TOKEN=ваш_токен node set-webhook.js https://ваш-сайт.netlify.app ваш_секрет
```
(`ваш_секрет` указывайте только если задавали `WEBHOOK_SECRET` в переменных окружения).

Скрипт выведет ответ Telegram и текущую информацию о вебхуке — убедитесь, что там
`"ok": true`.

## Шаг 5. Проверка

1. Добавьте себя в `INITIAL_MANAGEMENT` (или через переменные окружения).
2. Напишите боту `/start` — должно появиться меню менеджмента.
3. Нажмите «➕ Добавить нового персонала», отправьте, например:
   `test_user/TestRoblox/05.09.2026`
4. Попросите этого человека (или сами со второго аккаунта) написать `/start` —
   должно открыться меню персонала с профилем.
5. Проверьте `/delete test_user Прогулы` — сотрудник должен получить сообщение
   об увольнении, а доступ пропасть.

## Как устроена логика (кратко)

- **`/start`** — бот смотрит на `username` (ник в Telegram) отправителя:
  - если он в списке менеджмента → меню менеджмента;
  - если он в списке персонала → меню персонала, «Личный профиль»;
  - иначе → «нет доступа».
- **Меню персонала**: кнопка «Личный профиль» показывает ник, tg id, кол-во смен,
  ранг, баксы.
- **Меню менеджмента**:
  - «Список персонала» — весь список одним сообщением;
  - «Добавить нового персонала» — бот просит прислать сообщение в формате
    `НикТГ/НикRoblox/Дата устройства`, парсит и сохраняет;
  - «Выдать баксы» — бот спрашивает ник сотрудника, затем сумму, начисляет
    и уведомляет сотрудника личным сообщением.
- **`/delete НикТг Причина`** (только для менеджмента) — удаляет сотрудника из
  списка, отправляет ему уведомление об увольнении с причиной, доступ пропадает
  (при следующем `/start` он получит «нет доступа»).
- **`/cancel`** — отменяет текущий начатый диалог (например, если передумали
  добавлять сотрудника).

## Важные ограничения и что стоит знать

- Бот определяет сотрудников **по username** (нику в Telegram, без @). Если у
  человека не задан username в настройках Telegram, добавить его через ник
  не получится — либо попросите его установить username, либо доработайте
  логику под добавление по числовому `tg id` (это тоже реализуемо, но id
  сотрудник должен будет прислать вам сам, например через @userinfobot).
- Поля «смен посещено» и «ранг» сейчас можно менять только напрямую через код/
  расширение бота (в вашем ТЗ не было отдельной команды для этого) — если
  нужно, легко добавить ещё пару кнопок/команд по аналогии с «Выдать баксы»
  (посмотрите функции `updateStaff` в `storage.js` и `handleGiveBucksAmount`
  в `handlers.js` — новая функция строится по такому же шаблону).
- Диалоги «добавить сотрудника» / «выдать баксы» хранятся в Blobs по `chatId`,
  поэтому даже если функция «засыпает» между сообщениями (это нормально для
  serverless), бот не теряет, на каком шаге диалога находится менеджер.
- Секретный токен вебхука (`WEBHOOK_SECRET`) не обязателен, но рекомендуется —
  без него теоретически кто угодно может слать POST-запросы на адрес вашей
  функции, притворяясь Telegram.

## Локальная разработка (по желанию)

```bash
npm install -g netlify-cli
cd tg-netlify-bot
npm install
netlify dev
```
`netlify dev` поднимет функции локально, но чтобы Telegram мог до них достучаться,
понадобится туннель (например, `ngrok http 8888`) и временная установка вебхука
на адрес туннеля через `set-webhook.js`.
